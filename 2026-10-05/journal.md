## Round: kernel views + link deliverables + config levers (13:15)

The last two non-codegen errors decoded, and the puzzle explained:

- Base TUs were never excused by any config -- the reference compiles them
  inside `kernel.full` (an executable), whose TUs only ever compare in the
  executable stage against the Bazel kernel target's TUs, of which there are
  none (the kernel rule compiles nothing; its objects live in the cc_* target
  the union already verifies). The only kernel TU that actually compared in
  the `<libraries>` union was force-dynamic-hack.c: the reference compiles it
  under its own shared-library target, and the Bazel TU on the other side is
  cc_060's. So the two findings were real and only for that TU.
- flags_diff: the reference spells the toolchain-selection family JOINED
  (`--sysroot=<abs>`, `-B<abs>`, `--ld-path=<abs>`) there, and the paired
  spellings were dropped in code while joined ones survived. Fixed in the
  tool (canonicalize: `_is_joined_toolchain_flag`, same drop in links, and
  `-o`/`-B` in the link pair flags, depfile bookkeeping dropped on the link
  line too). Committed wt-freebsd 6c1786d.
- includes_diff (layout links machine/x86/i386 -> sys/*/include): the layer
  staged *copies* under $(GENDIR)/sys/BZL (machine_links genrule, 300+ lines

## Round: views re-homed + the DT_NEEDED fix; parity CONVERGED; boot proven (13:45-14:20)

- Round 2 (`//sys/...` as TARGETS) regressed catastrophically (219 errors,
