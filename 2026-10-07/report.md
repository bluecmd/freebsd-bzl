## What was done

1. **Parity RED at `//...` fixed** — the host-tool targets declared
   linux-only (`target_compatible_with`), so the kernel-platform wildcard
   skips them; build and diff look at the same target set again.
2. **Release target** — `bazel/image/` (BUILD.bazel, base.bzl repository
   rule pinning the release base.txz by sha256, make-rootdisk.py, rc,
   authorized_keys): Bazel-built makefs populates a 256MB FFSv2 root disk
   from the pinned base.txz (boot-test subset + shared-library closure via
   readelf BFS; mtree spec forces root ownership without chown(2) in the
   sandbox); the kernel is a copy genrule. `release.yml` builds
   `//bazel/image:image` and boots its outputs with TEST_SSH_KEY.
3. **IDIOM, wave 1** — the 61 kernel codegen genrules became
   `bazel/rules/kernel_generator.bzl` (`awk_generate` rule class
   AwkGenerate, one action per output, tool = the layer-built
   `//usr.bin/awk:awk`; `makeobjops` macro). Wiring:
   `codegen.mnemonics` += AwkGenerate in `models/kernel/any2bazel.json`;
   `EXTRA_MNEMONICS` in projects/freebsd/project.env carries it for
   parity.sh's aquery filter. One content trap: awk stamps the source path
   it was *given* into the output's provenance comment (` *   <path>.m`);
   the makefiles passed it absolute and the reference records carry that
   spelling, so the rule names the source `$PWD/<path>` like the genrule it
   replaced — and `content_ignore_lines` had to cover *any* spelling of
   that line (`^ \*   .+\.m$`), because `_key_argv_echoes` rewrites the
   bazel side's line to the input's logical key. IDIOM 38.4 → 27.4.
4. **IDIOM, wave 2** — the 15 recipe-replay genrules became domain rules:
   - `bazel/rules/kernel_steps.bzl`: `gen_offsets` (genassym.sh /
     genoffset.sh over the compile-products archive), `rpcgen_xdr` (one
     action per .x output), `newvers` (newvers.sh + the `make -V` shim),
     `vdso_image` (the sys/tools/*_vdso.sh drivers), `acpi_wakecode`
     (objcopy/nm/file2c pipeline), `kernel_config` (config(8) over
     sys/amd64/conf/BZL into the staged compile directory).
   - `bazel/rules/yacc_lex.bzl`: `yacc_generate` (m4's parser, awk's
     grammar, config's grammar) and `lex_generate` (config's scanner with
     the m4boot-on-PATH contract).
   Each rule runs the tree's own drivers with the tree's environment; the
   rule is the build step, not a copied recipe. `force-dynamic-hack.c`
   stayed a (marker-free) genrule — Bazel has no native empty-file rule
   here and a single-use rule class for `: > file` would be ceremony.
   flex's `skel` and awk's `proctab` genrules lost their pointless
   `$$PWD` env staging (inlined command substitution / direct invocation).
   The copy-shaped genrules became `copy_file` (bazel_skylib, already a
   dep): lex parse_h, rpcgen rpc_types, cross-build bitcount_copy.
   IDIOM 27.4 → 10.3 → 8.9 (genrules 24 → 7, none flagged).
5. **Gates re-proven on the final tree**: parity round 7 (converged,

## Trade-offs (deliberate)

- **packages_vs_dirs (8.8/10) stays**: 20 packages for 167 source
  directories. The kernel is one package (sys/BZL); its cc_NNN
  compile-product archives are load-bearing in the verified link (the
  artifact evidence pins their composition and the link order), so
  re-grouping sources per directory would break artifact parity. Splitting
  would also orphan the root package's sys/** filegroups. The guard rail
  outranks the score.
- `conventions.json` not provided: the hermeticity detector already scores
  0 and the hermetic gate proves no host-tool leakage; an inaccurate
  listing would be worse than none.
- 132 warnings remain (extra_generated by-products, extra_tu/extra_target
  from the layer's host-tool packages, and the G3 generator-tool warnings
  for the 71 kernel codegen outputs — all content-verified).

## Recommendations for the shared scripts (not changed, per instructions)

- `bin/parity.sh` builds its aquery mnemonic filter from a fixed literal
  plus `EXTRA_MNEMONICS`; extract_bazel.py already reads the project's
  `any2bazel.json` `codegen.mnemonics` (config.py documents it as "a
  codegen.mnemonics line in any2bazel.json, not a code change"). The filter
  should be seeded from the project's config (or the consumption rule given
  a query path), so a layer that adds a custom codegen rule class does not
  need to mirror the mnemonic list in project.env.
- `projects/freebsd/build-image.sh` is the pre-image acceptance path: it
  builds `KERNEL_TARGET` and, if root.img is missing, the *prototype* root
  disk from projects/freebsd/image/make-rootdisk.sh with the reference's
  bootstrapped makefs. The deliverable now is `//bazel/image:image`; the
  script should build that target and copy `bazel-bin/bazel/image/kernel`
  and `bazel-bin/bazel/image/root.img` (release.yml already does exactly
  this), keeping the prototype recipe as a cross-check.
